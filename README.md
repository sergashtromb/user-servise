# user-servise

# Требования

- Хранение пользователей (создание, редактирование, получение)
- Логирование событий изменений в бд а так же неудачных попыток (отдельная таблица бд)
- Кеширование сохранять получаемые данные в кеше Redis
- Для бд использовать PostgresSQL, черех pgx ограничивать количество одновременных запросов
- GRPs доступ
- реализация rate limiter (использовать готовые библиотеки)
- динамическое изменение настроек через http, а так же файл .yaml

# Будущие доработки

## Маштабирование логирования

Конкретно сейчас логгер отправляет сообщения в базу батчами с периодичностью и существуют проблемы:
1. При падении postgres логи нигде не сохраняются 
2. Логи пишутся в туже бд где и хранятся пользователи - к быстродействию при большой нагрузке
3. Сама по себе Postgres не лучшая бд для логов
4. Логгер не универсальный нельзя прокинуть например request id из middleware и отслеживать выполнение конкретного запроса

Как решить эти проблемы?
- Добавить слой сохранения логов на диск appendonly либо самописная, либо готовое решения с ротацией файлов при превышении ограничения на размер, либо sqlite в WAL режиме.
- Добавить фоновую очистку уже отправленых 
- Добавить очередь, после успешного сохранения на диск отправлять в очередь (redis streams например), и уже из очереди отправлять в бд
- Заменить postgres на clickhouse он быстрее
- Сделать возможность универсального включения слоев, например негде хранить логи возле приложения, отключить слой с сохранением на диск, не где хранить очередь отключили отправку в очередь батчим сами и отправляем в бд, нет бд пишем в stdout
